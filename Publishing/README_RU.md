# Публикация TWM Launcher (черновой комплект)

## Рекомендуемая архитектура

- GitHub Releases — хранение подписанных/проверяемых релизных пакетов и архивов рекомендуемых сборок.
- `update-manifest.json` — описание текущего релиза, минимальной версии и SHA-256 пакета.
- `recommended-catalog.json` — каталог рекомендуемых сборок/САМОФИКСов; обновляется независимо от версии лаунчера.
- Отдельный Windows Publisher — редактор каталога и помощник выпуска релизов. Он не должен содержать GitHub Personal Access Token в исходниках/конфигурации; авторизация — через GitHub CLI (`gh auth login`) или безопасный ввод секрета.
- Отдельный updater-процесс — проверяет манифест, загружает пакет во временную папку, сверяет SHA-256, закрывает лаунчер, заменяет файлы и запускает новую версию. При ошибке оставляет/восстанавливает предыдущую версию.

## Стратегия обновления

Для первой публикации используйте полный пакет `TWM-Launcher-win-x64.zip`, а не delta-обновления. Это проще и надёжнее для WPF/WebView2 и самодостаточной публикации. Delta-пакеты можно добавить позже, когда будет стабильная база пользователей.

## Важно перед подключением

1. Создайте публичный GitHub-репозиторий и Release с тестовым пакетом.
2. Укажите владельца/название репозитория в настройках публикации.
3. Сгенерируйте SHA-256 именно для загружаемого ZIP: `Get-FileHash .\TWM-Launcher-win-x64.zip -Algorithm SHA256`.
4. Не публикуйте пользовательские данные, ключи API или PAT в репозитории.
5. Пока GitHub repository не задан, автоматическая проверка обновлений намеренно не включена: нельзя безопасно угадывать источник обновления.

## Версии

При каждом релизе синхронно увеличивайте `Version`, `AssemblyVersion` и `FileVersion` в `AMM.App.csproj`, затем публикуйте приложение в Release-конфигурации.
